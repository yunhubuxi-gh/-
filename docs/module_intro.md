# 各模块详细说明

> 本科毕业设计论文模块说明章节素材，可直接引用修改。

## 一、RAG 引擎模块

### 1.1 模块概述

RAG（Retrieval-Augmented Generation，检索增强生成）引擎是系统的核心知识检索组件，负责将企业私有文档转化为可检索的知识，并根据用户问题召回相关文档片段供大模型生成答案。本模块实现了**多路混合召回 + 重排**的先进架构，有效解决单一召回模式的漏检与低精度问题。

### 1.2 混合召回架构

召回阶段采用 BM25 关键词召回与向量语义召回**两路并行**策略：

- **BM25 关键词召回**：基于词项匹配的稀疏检索方法，使用 `rank_bm25` 库实现 BM25Okapi 算法，搭配 jieba 中文分词。擅长精确匹配、专有名词、数字类问题。
- **向量语义召回**：基于嵌入相似度的稠密检索方法，将查询和文档块映射到同一高维语义空间，计算余弦相似度。擅长语义相似、意图模糊、同义表述类问题。

两路召回结果经过**去重融合**后，送入 BGE-Rerank 重排模型进行精排，最终返回 Top-N 最相关文档片段。

### 1.3 语义分块策略

传统固定长度分块（如按字符数切分）容易在语义边界处切断，导致召回的片段语义不完整。本系统实现**基于嵌入相似度的语义分块**：

1. 先将文档按句子切分为细粒度单元
2. 为每个句子生成嵌入向量
3. 计算相邻句子的相似度，当相似度低于阈值时判定为语义边界
4. 合并边界间的句子形成语义块
5. 兜底策略：如果语义块过大，使用递归字符分块进一步切分

### 1.4 幻觉抑制机制

为降低大模型幻觉，系统实施多层次抑制策略：

- **引用一致性校验**：生成答案后，校验答案中的每个事实性陈述是否能在召回文档中找到依据
- **无答案检测**：当召回文档与问题相关度极低时，模型明确回复"无法从现有知识库中找到答案"，而非强行编造
- **引用溯源标注**：每个回答附带来源文档名称、页码、原文片段，支持用户点击核验

### 1.5 文档版本管理

支持文档多版本管理：
- 每次上传同名文档自动创建新版本
- 向量索引按版本独立，可随时回滚到历史版本
- 保留版本变更记录与时间戳

## 二、Agent 智能模块

### 2.1 模块概述

Agent 模块基于 **LangGraph** 构建，实现具有任务拆解、规划执行、反思重试能力的有状态智能体。与简单的工具调用不同，本 Agent 具备完整的**规划 → 执行 → 反思**循环链路，能够处理复杂的多步骤任务。

### 2.2 LangGraph 状态图设计

Agent 以有向图形式组织，包含以下核心节点：

| 节点 | 职责 |
|------|------|
| Planner | 接收任务，拆解为有序子任务列表，为每个子任务指定工具与输入 |
| Executor | 按顺序执行子任务，调度对应工具，收集执行结果 |
| Reflector | 校验执行结果，判断是否成功；失败则分析原因，决定是否重试 |
| Responder | 所有子任务完成后，汇总结果并生成自然语言响应 |

条件边设计：
- Executor → Reflector（每次执行后必走）
- Reflector → Planner（失败且未达最大重试次数，重新规划）
- Reflector → Responder（成功或超过最大重试次数）

### 2.3 工具分类设计

Agent 内置工具集明确分为两大类，便于管理与权限控制：

**第一类：内部 RAG 检索工具**
- 知识库搜索工具：调用 RAG pipeline 从私有知识库检索文档片段
- 特点：只读操作，只访问内部知识库数据

**第二类：外部业务工具**
- 文档摘要工具：对指定文档生成结构化摘要
- 导出 CSV 工具：将会话记录或问答结果导出为 CSV 文件
- 周报生成工具：基于近期会话与文档生成工作周报
- 会话历史查询工具：查询当前或历史会话中的特定信息

### 2.4 记忆系统

**短期会话记忆**：采用滑动窗口 + 滚动摘要策略。保留最近 N 轮对话作为精确上下文，更早的对话由 LLM 生成摘要保留关键信息，平衡上下文长度与信息完整性。

**用户长期业务记忆**：将用户历史对话中的关键业务偏好、专有名词解释、个人习惯等信息提取并存入向量库。后续会话中，系统自动检索相关长期记忆融入上下文，实现跨会话的个性化交互。

## 三、用户与权限模块

### 3.1 用户模型

- 支持用户名 + 密码注册登录
- 密码使用 bcrypt 哈希存储，不可逆
- JWT 双令牌机制：Access Token（短时效）+ Refresh Token（长时效）
- 用户状态：正常 / 禁用

### 3.2 知识库权限隔离

采用**用户 — 知识库 多对多授权**模型：

- 每个知识库有一个所有者（创建者，拥有全部权限）
- 知识库可被授权给其他用户，权限级别分为：只读 / 读写 / 管理
- 所有文档、会话、问答操作均校验用户对知识库的访问权限
- 越权操作均记录审计日志

权限校验通过装饰器 + 服务层双重校验保证安全。

## 四、异步任务模块

### 4.1 设计动机

文档解析与向量化是 I/O 密集 + 计算密集型操作，大文档（如几百页 PDF）处理耗时可能达到数分钟。如果在 HTTP 请求中同步执行，会导致：
- 请求超时
- 服务器线程阻塞，影响并发能力
- 用户体验差，无进度反馈

### 4.2 实现方案

系统实现异步任务调度器，封装两种引擎，通过配置切换：

| 引擎 | 适用场景 | 特点 |
|------|---------|------|
| FastAPI BackgroundTasks | 开发环境 / 单机部署 | 轻量，无需额外组件，进程内线程执行 |
| Celery + Redis | 生产环境 / 分布式部署 | 支持任务持久化、重试、优先级、分布式扩展 |

异步任务应用场景：
- 大文档解析与向量化
- 批量知识库重建索引
- 文档版本回滚
- 大数据量导出

### 4.3 任务状态跟踪

每个异步任务分配唯一任务 ID，任务状态（等待/执行中/成功/失败）持久化存储，前端可轮询查询进度与结果。

## 五、审计日志模块

### 5.1 日志分类

- **请求日志**：所有 HTTP 请求的方法、路径、参数、状态码、耗时、客户端 IP
- **问答日志**：每次用户提问、召回文档、生成答案、耗时、token 用量
- **Agent 执行日志**：任务规划过程、每步工具调用、反思过程、最终结果
- **操作审计日志**：知识库创建/删除、权限变更、文档删除等关键操作

### 5.2 日志用途

- 系统运维：故障排查、性能监控
- 安全审计：越权尝试追溯、操作行为审计
- 效果优化：分析 bad case，迭代召回与生成策略
- 合规要求：企业内部数据访问留痕
