# 系统架构设计说明

> 本章节为本科毕业设计论文《系统架构设计》章节提供素材，可直接引用修改。

## 一、总体架构设计

### 1.1 架构设计思想

本系统采用**六层分层架构**，自上而下分别为：UI 表现层、API 接口层、业务服务层、AI 能力层、通用工具层、数据持久层。各层之间遵循**高内聚、低耦合**的设计原则，上层只能调用下层，下层不感知上层，保证模块职责清晰、易于扩展和维护。

架构设计遵循以下核心原则：

- **关注点分离**：将界面展示、接口协议、业务逻辑、AI 能力、基础设施解耦，各自独立演进
- **依赖倒置**：上层模块依赖抽象接口，而非具体实现（如向量库抽象基类、LLM 客户端封装）
- **可插拔设计**：关键组件（向量数据库、大模型、异步任务引擎）通过配置开关切换，无需修改业务代码
- **数据分离存储**：业务元数据、向量数据、原始文档三者分开存储，各自选择最适合的存储引擎

### 1.2 六层架构总览

```
┌──────────────────────────────────────────────────────────────┐
│  第 1 层   UI 表现层（Streamlit 多页面）                     │
├──────────────────────────────────────────────────────────────┤
│  第 2 层   API 接口层（FastAPI RESTful）                     │
├──────────────────────────────────────────────────────────────┤
│  第 3 层   业务服务层（Services）                             │
├──────────────────────────────────────────────────────────────┤
│  第 4 层   AI 能力层（RAG 引擎 + Agent 智能）                │
├──────────────────────────────────────────────────────────────┤
│  第 5 层   通用工具 Utils 层                                 │
├──────────────────────────────────────────────────────────────┤
│  第 6 层   数据持久层（关系型 DB + 向量库 + 文件系统）        │
└──────────────────────────────────────────────────────────────┘
```

## 二、各层详细说明

### 2.1 第 1 层 — UI 表现层

基于 Streamlit 构建的 Web 管理界面，采用多页面架构，包含：

- **登录页**：用户身份认证入口
- **知识库管理**：知识库的创建、编辑、删除、用户授权
- **文档管理**：文档上传、列表、版本管理、向量化状态查看
- **智能问答**：基于 RAG 的普通问答模式，支持流式输出与引用来源展示
- **Agent 任务**：复杂任务模式，展示 Agent 规划过程、工具调用、反思重试链路
- **日志审计**：请求日志、问答日志、Agent 执行日志的查询与检索

### 2.2 第 2 层 — API 接口层

基于 FastAPI 构建的 RESTful API 服务，职责包括：

- **JWT 鉴权**：访问令牌 + 刷新令牌双令牌机制
- **请求日志中间件**：记录所有 HTTP 请求的入参、耗时、状态码
- **全局异常处理**：统一错误码与响应格式，前端统一处理
- **参数校验**：基于 Pydantic 的请求/响应 DTO 校验
- **路由版本管理**：使用 `/api/v1` 前缀，支持未来 API 版本迭代

接口按业务域划分为：认证、知识库、文档、问答、Agent、会话、审计日志。

### 2.3 第 3 层 — 业务服务层

业务逻辑编排层，封装核心业务规则，API 层不直接操作数据或调用 AI 能力。

- **AuthService**：用户注册、登录、令牌刷新、密码校验
- **KBService**：知识库 CRUD、用户授权、权限校验
- **DocumentService**：文档上传元数据写入、触发异步解析与向量化
- **ChatService**：普通 RAG 问答编排、会话管理、引用组装
- **AgentService**：Agent 任务创建、状态跟踪、执行日志记录
- **AuditService**：审计日志写入与查询

> **异步任务设计**：大文档上传与向量化是耗时操作，服务层通过 `TaskScheduler` 将任务提交到异步引擎，立即返回任务 ID 给前端，避免 HTTP 请求阻塞。开发环境使用 FastAPI BackgroundTasks，生产环境切换为 Celery + Redis。

### 2.4 第 4 层 — AI 能力层

系统的核心智能层，由 RAG 引擎子模块和 Agent 智能子模块共同组成。

#### RAG 子模块（混合检索增强生成）

| 组件 | 功能说明 |
|------|---------|
| 文档解析 | 支持 PDF / DOCX / Markdown 解析，扫描版 PDF 自动触发 OCR |
| 语义分块 | 基于嵌入相似度的语义边界检测，避免块断裂语义；递归分块兜底 |
| BM25 召回 | 基于关键词的稀疏检索，处理精确匹配类问题 |
| 向量召回 | 基于嵌入的稠密语义检索，处理语义相似类问题 |
| BGE 重排 | 两路召回结果融合后，用 BGE-Rerank 精排，提升前 N 条准确率 |
| 幻觉抑制 | 回答生成后做引用一致性校验，与无答案检测 |
| 引用标注 | 回答标注来源文档名称、页码、原文片段，可追溯 |
| 文档版本管理 | 支持文档版本迭代、增量更新、历史版本回滚 |

#### Agent 子模块（LangGraph 智能体）

基于 LangGraph 构建有状态智能体，采用**规划 → 执行 → 反思**三节点循环架构：

- **Planner 节点**：接收用户任务，拆解为子任务序列，为每个子任务选择对应工具
- **Executor 节点**：按子任务顺序调度工具执行，收集执行结果
- **Reflector 节点**：校验执行结果质量，若失败则分析原因、调整策略、重新规划
- **Responder 节点**：所有子任务完成后，汇总结果生成最终响应

**工具分类设计**（两类工具职责明确）：

1. **内部 RAG 检索工具**：知识库搜索工具（调用 RAG pipeline 检索内部文档）
2. **外部业务工具**：文档摘要、导出 CSV、周报生成、会话历史查询

**记忆模块**：
- **短期会话记忆**：滑动窗口 + 滚动摘要，保证上下文连贯
- **用户长期业务记忆**：向量存储用户业务偏好、历史关键信息，跨会话调用

### 2.5 第 5 层 — 通用工具 Utils 层

系统基础设施层，向上层提供公共能力，避免工具函数散落各处。

| 模块 | 功能说明 |
|------|---------|
| config_loader | 配置加载与热更新，统一管理所有配置项 |
| llm_client | LLM 客户端封装（OpenAI 兼容协议），支持同步/异步/流式，统一切换模型 |
| embedding_client | 嵌入模型客户端（BGE / OpenAI 兼容） |
| ocr_engine | OCR 引擎封装（PaddleOCR / Tesseract 可切换） |
| error_codes | 统一错误码体系，业务错误码与 HTTP 状态码映射 |
| exceptions | 自定义异常类体系（业务异常、鉴权异常、RAG 异常等） |
| response | 统一响应封装（success / fail / error 格式） |
| security | 安全工具（bcrypt 密码哈希、JWT 签发与校验） |
| file_utils | 文件处理（格式检测、路径安全校验、大小校验） |
| text_utils | 文本处理（中文分词、文本清洗、归一化） |
| permission | 权限校验装饰器与工具函数 |
| async_task | 异步任务封装（BackgroundTasks / Celery 可切换引擎） |
| logger | 统一日志器（多级别、滚动、审计日志独立通道） |

### 2.6 第 6 层 — 数据持久层

采用**三者分离存储**设计，针对不同数据类型选择最适合的存储引擎。

#### 设计理由

| 数据类型 | 存储引擎 | 选择理由 |
|---------|---------|---------|
| 业务元数据（用户、知识库、文档元信息、会话、日志） | PostgreSQL | 结构化数据、需事务保证、支持复杂关联查询与权限校验 |
| 向量嵌入数据 | Chroma / Milvus（二选一） | 高维向量专用近似最近邻搜索，独立扩展读写性能 |
| 原始文档文件 | 文件系统（本地 / 对象存储） | 二进制大文件存数据库性能差、备份慢；文件系统便于直接访问与 OCR 重跑 |

#### 向量库可插拔设计

- **Chroma**：本地开发 / 轻量部署，无需额外部署服务，数据持久化到本地磁盘
- **Milvus**：企业生产部署，支持分布式、高并发、亿级向量检索
- 通过配置项 `VECTOR_STORE_TYPE` 切换，代码不写死两套同时依赖

## 三、核心数据流

### 3.1 文档入库流程

```
用户上传文档 → DocumentService 写入元数据 → 返回任务ID
                   ↓ 异步
           格式检测 → 解析器分发 → 文本提取
                   ↓
           语义分块 → Embedding 生成
                   ↓
           向量库写入 + BM25 索引构建
                   ↓
           更新文档状态为"已就绪"
```

### 3.2 问答流程（普通 RAG 模式）

```
用户提问 → Query 改写 → 并行召回(BM25 + 向量)
                   ↓
           融合去重 → BGE-Rerank 精排 TopN
                   ↓
           构建 Prompt（含引用上下文）
                   ↓
           LLM 生成答案 → 幻觉检测 → 引用标注 → 返回
```

### 3.3 Agent 任务流程

```
用户任务 → AgentManager 启动
                   ↓
           Planner 节点：拆解子任务 + 工具选择
                   ↓
           Executor 节点：逐个执行子任务（调用工具）
                   ↓
           Reflector 节点：结果校验 / 失败分析 / 重试判断
                   ↓
        ┌─ 成功 → Responder 汇总输出
        └─ 失败且未超重试 → 返回 Planner 重新规划
```

## 四、关键技术选型

| 领域 | 技术选型 | 说明 |
|------|---------|------|
| Web 后端 | FastAPI | 高性能异步框架，自动生成 OpenAPI 文档 |
| Web 前端 | Streamlit | 快速构建数据类 Web 应用，适合内部工具 |
| 关系型数据库 | PostgreSQL / SQLite | 生产用 PG，开发用 SQLite |
| 向量数据库 | Chroma / Milvus | 二选一配置切换 |
| ORM | SQLAlchemy + Alembic | 数据模型 + 迁移版本管理 |
| LLM 框架 | LangChain + LangGraph | RAG 链路 + Agent 状态图 |
| 重排模型 | BGE-Rerank | 中文效果优秀的开源重排模型 |
| 嵌入模型 | BGE-Embedding | 中英双语开源嵌入模型 |
| 异步任务 | FastAPI BackgroundTasks / Celery | 开发/生产两套方案可切换 |
| 部署 | Docker Compose | 一键部署，环境隔离 |
| 鉴权 | JWT 双令牌 | 无状态认证，支持刷新 |
