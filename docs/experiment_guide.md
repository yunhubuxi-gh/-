# 实验设计与效果对比指南

> 本科毕业设计论文《实验与分析》章节素材。
> 包含实验环境、评价指标、对比实验设计、结果分析建议。

## 一、实验环境

### 1.1 硬件环境

| 项目 | 配置 |
|------|------|
| CPU | Intel Core i7-13700 / AMD Ryzen 7 7800X3D 或以上 |
| 内存 | 32GB DDR5 |
| GPU | NVIDIA RTX 3060 12GB 或以上（用于本地嵌入与重排模型） |
| 存储 | 500GB SSD |

### 1.2 软件环境

| 项目 | 版本 |
|------|------|
| 操作系统 | Windows 11 / Ubuntu 22.04 |
| Python | 3.11 |
| FastAPI | 0.115.x |
| 关系型数据库 | PostgreSQL 16 / SQLite 3 |
| 向量数据库 | Chroma 0.5.x 或 Milvus 2.3.x |
| 大模型 | GPT-4o-mini / DeepSeek-V3 / Qwen-Plus |
| 嵌入模型 | BAAI/bge-small-zh-v1.5 |
| 重排模型 | BAAI/bge-reranker-base |

### 1.3 测试数据集

建议使用以下三类数据进行实验：

1. **公开评测集**：CMRC2018（中文阅读理解）、DRCD（繁体中文阅读理解）中抽取 100 个问答对
2. **企业模拟数据**：构造 5~10 份企业内部文档（员工手册、产品文档、规章制度等），人工标注 50 个问答对
3. **真实业务数据**（如有条件）：从目标企业获取脱敏后的内部文档与真实用户问题

每个问答对应包含：
- `question`：用户问题
- `answer`：参考答案（人工标注）
- `evidence`：答案在文档中的来源段落（用于召回评估）
- `source_doc`：来源文档名称与页码

## 二、评价指标

### 2.1 召回效果指标

| 指标 | 全称 | 含义 |
|------|------|------|
| Recall@K | 召回率 | Top-K 召回结果中包含正确证据的比例 |
| Precision@K | 精确率 | Top-K 召回结果中相关结果所占比例 |
| MRR | 平均倒数排名 | 第一个相关结果位置的倒数平均值 |
| NDCG@K | 归一化折损累计增益 | 考虑排序位置的综合评价指标 |

### 2.2 问答效果指标

| 指标 | 方法 | 说明 |
|------|------|------|
| 答案准确率 | 人工评估 + LLM-as-Judge | 答案是否正确回答了问题，1~5 分打分 |
| 幻觉率 | 人工评估 + 引用一致性校验 | 答案中无法从引用文档验证的陈述比例 |
| 引用准确率 | 自动统计 | 答案引用来源是否真实支撑对应陈述 |
| ROUGE-L | 自动计算 | 与参考答案的最长公共子序列 F1 值 |
| BLEU | 自动计算 | n-gram 重叠度（适合短句场景参考） |

### 2.3 Agent 效果指标

| 指标 | 含义 |
|------|------|
| 任务成功率 | 任务最终成功完成的比例 |
| 平均重试次数 | 每个任务平均经过几次反思重试才完成 |
| 规划准确度 | 第一次规划就能选对工具与步骤的比例 |
| 平均任务耗时 | 从任务提交到完成的平均时长 |

### 2.4 系统性能指标

| 指标 | 含义 |
|------|------|
| QPS | 每秒并发问答请求数 |
| 平均响应时间 | 单次问答从请求到首字/完整返回的时间 |
| 文档处理吞吐量 | 每小时能处理的文档页数 / 字数 |
| 向量索引构建速度 | 每万条向量的索引构建时间 |

## 三、对比实验设计

### 实验一：不同召回策略对比

**目的**：验证混合召回 + 重排相对于单一召回方法的提升。

**实验组**：
1. BM25 关键词召回（基线）
2. 向量语义召回（仅稠密检索）
3. BM25 + 向量 混合召回（等权重融合）
4. BM25 + 向量 + BGE-Rerank（完整方案）

**评价指标**：Recall@5 / Recall@10 / MRR / NDCG@10

**预期结论**：混合召回优于单一召回，加重排后进一步提升 Top-K 准确率。

### 实验二：分块策略对比

**目的**：验证语义分块相对于固定长度分块的效果提升。

**实验组**：
1. 固定长度分块（512 字符，重叠 50）—— 基线
2. 递归字符分块（LangChain RecursiveCharacterTextSplitter）
3. 语义分块（基于嵌入相似度的语义边界检测）—— 本文方案

**评价指标**：
- 召回效果（Recall@K）
- 答案质量（人工打分、幻觉率）
- 平均分块数、平均块大小

**预期结论**：语义分块在相同块数量下召回准确率更高，答案引用更精确。

### 实验三：幻觉抑制效果评估

**目的**：验证幻觉抑制机制是否有效降低幻觉率。

**实验组**：
1. 纯 LLM 问答（无 RAG，基线）
2. RAG 问答（无幻觉检测）
3. RAG + 引用一致性校验 + 无答案检测（完整方案）

**评价指标**：
- 幻觉率（人工标注答案中幻觉陈述的比例）
- 拒答准确率（无答案时正确拒绝的比例）
- 用户满意度（1~5 分）

**预期结论**：幻觉抑制模块可显著降低幻觉率，无答案场景下正确拒答。

### 实验四：Agent 反思重试效果

**目的**：验证反思重试机制对复杂任务成功率的提升。

**实验组**：
1. 无反思的单轮工具调用（基线，相当于普通 ReAct）
2. 反思重试（最多 1 次重试）
3. 反思重试（最多 3 次重试）—— 本文方案

**测试任务集**（建议 20~30 个任务）：
- 文档摘要类
- 信息检索 + 导出类
- 多步问答类
- 周报生成类

**评价指标**：任务成功率、平均重试次数、平均耗时

**预期结论**：反思重试机制显著提升复杂任务成功率，但增加平均耗时；3 次重试是效果与效率的平衡点。

### 实验五：不同向量库性能对比

**目的**：对比 Chroma 与 Milvus 在不同数据规模下的性能差异。

**数据规模**：1万 / 10万 / 100万 条向量

**评价指标**：
- 单查询平均耗时（Top-10）
- 并发 10 / 50 / 100 QPS 下的平均延迟
- 索引构建时间
- 内存占用

**预期结论**：小规模数据两者性能接近，大规模数据下 Milvus 性能显著优于 Chroma。

### 实验六：系统并发性能测试

**目的**：评估系统整体并发能力。

**工具**：Locust 或 JMeter

**测试场景**：
- 纯问答接口压力测试
- 文档上传接口压力测试（含异步处理）
- 混合场景（70% 读 + 30% 写）

**评价指标**：QPS、P50/P95/P99 延迟、错误率

## 六、测试脚本框架（参考）

```python
# tests/experiment/eval_recall.py  示意
def evaluate_recall(qa_pairs, retriever, top_k_list=[5, 10]):
    """评估召回效果"""
    results = {f"recall@{k}": 0 for k in top_k_list}
    results["mrr"] = 0
    total = 0

    for qa in qa_pairs:
        retrieved = retriever.retrieve(qa["question"], top_k=max(top_k_list))
        retrieved_ids = [doc.chunk_id for doc in retrieved]

        # 计算 Recall@K
        for k in top_k_list:
            if any(doc_id in qa["evidence_ids"] for doc_id in retrieved_ids[:k]):
                results[f"recall@{k}"] += 1

        # 计算 MRR
        for rank, doc_id in enumerate(retrieved_ids, 1):
            if doc_id in qa["evidence_ids"]:
                results["mrr"] += 1.0 / rank
                break

        total += 1

    for k in top_k_list:
        results[f"recall@{k}"] /= total
    results["mrr"] /= total
    return results
```
