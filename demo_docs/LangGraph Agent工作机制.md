# LangGraph Agent 工作机制

> 文档用途：企业私有知识库智能助手 · AI 技术知识库演示素材
> 适用场景：介绍基于 LangGraph 的智能 Agent 如何自主拆解任务、调用工具、反思重试

## 一、什么是 Agent

Agent（智能体）是一类能够自主规划、调用工具、执行任务并自我修正的 AI 程序。与传统"一问一答"的聊天机器人不同，Agent 面对一个复杂任务时，会：

1. 先把任务拆解成若干可执行的子步骤。
2. 决定每一步调用哪个工具（例如知识库检索、文档摘要、CSV 导出）。
3. 执行工具并观察结果。
4. 如果某一步失败，分析失败原因、调整策略并重试。

## 二、为什么用 LangGraph

LangGraph 是一个用于构建有状态、多步骤 AI 工作流的框架。它的核心是「状态图（StateGraph）」，把 Agent 的执行过程建模成一张有节点、有边、有状态的图，从而让执行流程清晰、可控、可观测。

相比简单的"提示词 + 工具调用"串行脚本，LangGraph 的优势在于：

- 执行流程可显式建模，便于理解和调试。
- 支持条件路由，根据执行结果动态决定下一步走哪个节点。
- 状态在节点间传递，天然支持多轮规划与反思。

## 三、Agent 的闭环执行流程

本系统的 Agent 采用「规划 → 执行 → 反思」的闭环：

### 1. 规划节点（Planner）

接收用户任务，调用大模型将任务拆解为若干步骤，每一步指定要使用的工具和期望目标。

### 2. 执行节点（Executor）

按规划逐步调用工具。工具分为两类：

- **内部工具**：知识库 RAG 检索，用于从私有文档中查找信息。
- **外部业务工具**：文档摘要、CSV 数据导出等。

任一工具执行失败时，立即停止，记录错误信息，并将状态标记为失败。

### 3. 反思节点（Reflector）

当执行失败时，Agent 进入反思节点：分析失败原因（例如"检索无结果""工具参数错误"），生成修正策略（例如"换用更宽泛的关键词重新检索"），然后将重试次数加一，回到规划节点重新规划。

### 4. 重试上限

为防止 Agent 陷入死循环，系统设置了最大重试次数。当重试次数达到上限仍未成功时，Agent 停止执行，返回失败结果并附带错误说明。

## 四、记忆机制

- **短期记忆**：滑动窗口保存最近若干条交互消息，让 Agent 保持上下文连贯。
- **长期记忆**：把用户偏好、历史经验持久化到磁盘，供后续任务检索复用。

## 五、一句话总结

LangGraph Agent 的价值在于：**让 AI 从"被动回答"升级为"主动执行"**，通过「规划-执行-反思重试」的闭环，自主完成复杂任务。
