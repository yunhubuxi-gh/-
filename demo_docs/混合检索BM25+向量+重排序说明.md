# 混合检索：BM25 + 向量 + 重排序 说明

> 文档用途：企业私有知识库智能助手 · AI 技术知识库演示素材
> 适用场景：介绍本系统多路召回与精排的技术细节

## 一、为什么需要混合检索

单一的检索方式各有短板：

- **纯关键词检索（如 BM25）**：只能匹配字面相同的词。用户问"怎么请假"，文档里写的是"休假申请流程"，关键词检索就匹配不到。
- **纯向量语义检索**：能理解语义，但对精确的编号、专有名词、数字等不够敏感，容易出现"答非所问"。

混合检索把两种方式的优势叠加，用关键词检索保证"精确命中"，用向量检索保证"语义理解"，从而整体提升召回率。

## 二、BM25 关键词检索

BM25 是经典的概率检索模型，核心思想是：

1. 对文档进行分词（中文使用 jieba 分词）。
2. 根据词频和逆文档频率给每个词打分，出现频率高且文档中少见的词权重更高。
3. 对用户查询中的每个词，累加其在候选文档中的得分，得到该文档的相关性分数。

本系统将 BM25 索引持久化到磁盘，检索时按 top_k 返回得分最高的文档分块。

## 三、向量语义检索

向量检索的流程是：

1. 将文档分块通过嵌入模型（BGE）编码成向量。
2. 将用户问题同样编码成向量。
3. 计算问题向量与所有文档分块向量的相似度（通常用余弦相似度），返回最相似的分块。

向量检索的核心优势是"语义匹配"：即使措辞不同，只要含义相近，也能被检索到。

## 四、加权融合

两路检索分别返回一批候选分块，融合的步骤是：

1. **min-max 归一化**：把 BM25 分数和向量相似度分数各自归一化到 0~1 区间，消除量纲差异。
2. **加权求和**：按权重加权，本系统采用「向量 0.7 + BM25 0.3」的比例，更侧重语义。
3. **去重**：同一分块可能被两路同时召回，按分块 ID 去重。

## 五、重排序精排

融合后的候选列表再交给重排序模型（BGE-Rerank）二次打分。重排序模型会逐对计算「问题-候选分块」的相关性，比单靠向量相似度更精准，最终取 top_k 作为增强上下文。

若重排模型未安装，系统会自动降级为「词重叠打分」，保证功能可用。

## 六、完整链路回顾

```
用户问题
  → BM25 关键词召回 ┐
                    ├─ min-max 归一化 → 加权融合(0.7向量+0.3BM25) → 去重
  → 向量语义召回 ┘                     → BGE-Rerank 精排 → top_k 上下文 → 大模型生成
```

## 七、一句话总结

混合检索的本质是：**用多路召回保证"找得到"，用重排序保证"排得准"**。
